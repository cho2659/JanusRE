제거 권장 파일 및 폴더

- frida_agent/node_modules/: package-lock.json 기반으로 재설치 가능한 의존성 폴더.
- .venv/: 로컬 Python 가상환경.
- old/: 레거시 코드 보관 폴더. 필요한 이력은 Git 이력이나 문서로 대체 권장.
- agent/: 현재 런타임 경로가 frida_agent/agent.js라면 중복/구버전 산출물로 보임.
- agent/agent copy.js: 공백 포함 복사본 파일명과 중복 산출물.
- agent/old_agent.js: 구버전 산출물.
- frida_agent/old/: 레거시 agent 소스. 필요한 비교 근거가 없으면 제거 권장.
- readme.txt: 최소 README.md로 대체 권장.
- CLAUDE.md: AGENTS.md와 역할이 중복되면 통합 권장.

GitHub 공개 전 코드베이스 품질 개선 절차

1. 저장소 기준 실행 경로 정리
   - bridge_server.py, ghidra_side/frida_bridge.py, frida_agent/agent.ts/agent.js의 단일 진실 원천을 명확히 한다.
   - Ghidra가 실제로 실행하는 외부 복사본(E:/openhwp/custom_tools/ghidra_addon/frida_bridge.py) 동기화 절차를 문서화하거나 제거한다.

2. 패키징과 실행 문서 정리
   - README.md에 Windows x64, Python, PySide6, Frida, Ghidra 스크립트 설치/실행 절차를 작성한다.
   - frida_agent는 npm install 후 npm run build로 agent.js를 생성한다는 절차를 명시한다.

3. 테스트와 검증 명령 고정
   - python -m py_compile bridge_server.py ghidra_side/frida_bridge.py
   - npm run build (frida_agent)
   - 가능하면 저장/불러오기 JSON round-trip과 CallTreeBuilder 레이아웃 단위 테스트를 추가한다.

4. GUI 구조 분리
   - bridge_server.py 단일 파일에서 TraceSession, FridaWorker, GhidraServerWorker, graph view, panels를 모듈 단위로 분리한다.
   - 그래프 레이아웃 정책은 별도 순수 함수로 분리해 테스트 가능하게 만든다.

5. Ghidra 통합 안정화
   - Ghidra RPC 실패를 사용자 상태바 메시지로 정리하고 콘솔 traceback은 디버그 옵션에서만 출력한다.
   - Ghidra symbol cache의 lazy load, rename sync, export fallback 규칙을 문서화한다.

6. 트레이스 데이터 계약 정리
   - JSON에는 Frida 원천 이벤트와 모듈 타임라인만 저장한다.
   - Ghidra 기반 이름/주석/XRef 정보는 저장하지 않는다는 정책을 README와 코드 주석에 명시한다.

7. 린트와 포맷 도입
   - Python: ruff 또는 pyright/mypy 중 하나를 도입한다.
   - TypeScript: npm run build 외 eslint 스크립트를 CI에 연결한다.

8. 보안/공개 점검
   - 로컬 절대경로, 개인 사용자명, 분석 대상 바이너리, 대용량 생성물, node_modules, venv가 포함되지 않도록 확인한다.
   - 샘플 trace JSON에 민감한 경로/모듈 정보가 들어가지 않게 한다.

9. GitHub Actions 추가
   - Python 문법 검증과 frida_agent 빌드를 CI로 실행한다.
   - 의존성 캐시를 사용하되 node_modules 자체는 커밋하지 않는다.
